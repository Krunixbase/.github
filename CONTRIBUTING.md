# Contributing to Krunixbase

Thank you for your interest in contributing to the Krunixbase ecosystem.

Our mission is to build deterministic and auditable security software for researchers, organizations and individual users.

---

## Ways to Contribute

Contributions are welcome in the following areas:

### Development

- New features
- Bug fixes
- Performance improvements
- Testing

### Documentation

- README improvements
- Tutorials
- Examples
- API documentation

### Security Research

- Security reviews
- Code audits
- Threat modeling
- Vulnerability reporting

### Community

- Discussions
- Feedback
- Issue triage
- Project promotion

---

## Development Principles

Contributors should prioritize:

- Determinism
- Reproducibility
- Security
- Simplicity
- Privacy

---

## Pull Requests

Before submitting a Pull Request:

1. Ensure the code builds successfully.
2. Verify that existing functionality is not broken.
3. Keep changes focused and well documented.
4. Follow existing project conventions.
5. Include meaningful commit messages.

---

## Code Style

General preferences:

- Clear and readable code
- Explicit behavior over implicit behavior
- Minimal dependencies
- Security-conscious design

---

## Reporting Issues

If you find a bug, please open an issue and include:

- Project name
- Environment information
- Reproduction steps
- Expected behavior
- Actual behavior

---

## Community Standards

Please be respectful and constructive.

We value:

- Professional communication
- Technical accuracy
- Good-faith collaboration
- Open discussion

---

Thank you for helping improve the Krunixbase ecosystem.
